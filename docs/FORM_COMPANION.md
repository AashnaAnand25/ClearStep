# ClearStep Form Companion

## Demo now: no paid API

1. Run `ollama serve` in one terminal. If it is already listening on 11434, keep the existing instance.
2. On a new computer, run `ollama pull qwen2.5:7b` once (about 4.7 GB).
3. In this repository run `bun install --frozen-lockfile`, then `bun run dev`.
4. Open `http://127.0.0.1:3000/form-lab.html` (or the port printed by Vite).
5. Select **Extra withholding**, then **Even simpler**. The panel identifies generated output as Local AI. The source link stays visible.

Ollama and the model are installed on the demo Mac. The model runs on-device; no OpenAI credit is used by the companion's default configuration. The original preparation-plan explanation service still uses its separate OpenAI adapter and labelled fallbacks.

## Chrome extension

The unpacked extension is in `public/companion`. No build step is required for these files.

1. In Chrome open `chrome://extensions`, enable Developer mode, and choose **Load unpacked**.
2. Select `public/companion` inside this repository.
3. Open the practice form in Chrome. Choose **Use installed extension instead** to hide the embedded panel, then click the ClearStep extension icon.
4. Focus a supported field. The Chrome side panel explains it. Keep the app on port 3000 for the default connection.

The extension uses `activeTab` only after the user clicks the icon, `scripting` to listen for focused fields, and session storage for a canonical field ID. It does not read `.value`, send labels/URLs, save form answers, or autofill anything. Local storage holds only the configured backend address. Optional HTTPS host permission is requested only when the user saves a hosted backend.

Only HTML form controls with associated labels matching **multiple jobs/spouse works**, **other income (not from jobs)**, or **extra withholding** are recognized. This is intentionally a three-field W-4 prototype. PDF viewers, nested iframes, shadow DOM controls, unlabeled fields, and other forms are not supported. Similar wording on a non-W-4 form must not be treated as verified context: the panel explicitly names the W-4 step and links its instructions.

The website embeds the same panel and calls the same endpoint. Browser verification of the embedded panel does not by itself establish that Chrome's extension permission/lifecycle integration has been tested. Load the unpacked package and confirm this separately before recording an extension-specific claim.

## Hosted deployment later

Deploy a **Node server** from this repository, not just static files. Build with `bun install --frozen-lockfile && bun run build`; start with `node .output/server/index.mjs`. Configure the host's assigned `PORT` and `HOST=0.0.0.0` as needed.

Set server environment variables:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=your_funded_project_key
OPENAI_MODEL=gpt-4o-mini
CLEARSTEP_EXTENSION_IDS=your_chrome_extension_id
```

The extension's Connection settings page displays its ID. Enter your deployed HTTPS origin there and approve that host permission. Each unpacked install can have a different ID; use comma-separated IDs for test machines. Never put an API key into extension settings or frontend code.

Deployment does not change the billing status of an OpenAI key. The prior exhausted-credit error must be resolved for hosted OpenAI. A remote server cannot access Ollama on a visitor's laptop: either use funded OpenAI or operate your own model server on the deployment machine. The demo's local Ollama address is fixed to loopback.

The endpoint bounds request sizes, validates a strict field/mode allowlist, handles offline/invalid model output, uses a nine-entry cache, admits one generation at a time and caps generation attempts at 20/minute per process. Before broad public release add shared abuse controls, monitoring, and model-quality evaluation. An extension-ID origin check is not user authentication.

## Evidence and limitations

The three field summaries are assistant-reviewed paraphrases of the [2026 IRS W-4 and instructions](https://www.irs.gov/pub/irs-pdf/fw4.pdf), accessed October 3, 2026. Sources are fixed by the app, not generated by the model. ClearStep explains terms, not personal tax choices. It cannot choose amounts, filing status, exemptions or eligibility. AI may omit or misstate conditions; read the official instructions. Re-review when IRS revises the form.

Model: [Qwen2.5 7B](https://ollama.com/library/qwen2.5:7b), an open-weight model with its own license, served by [Ollama](https://docs.ollama.com/api/generate). Cloud structured responses follow the [OpenAI guide](https://developers.openai.com/api/docs/guides/structured-outputs). Extension implementation follows [Chrome's Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel).

If that is still too much, I can ask for simpler wording. The official IRS instructions are one click away. This demonstration runs real AI on the laptop. ## Additional guided forms

The web practice chooser now includes W-4, W-9, and DS-11, with three selected sections each. This is guidance, not full form completion or submission. Practice controls do not collect actual names, taxpayer numbers, addresses, or signatures. Switching forms clears practice selections and the previous explanation.

The shared catalog is public/companion/forms.json. Each form owns its official source URL and reviewed evidence, used by both the UI and server. W-9 evidence was checked against https://www.irs.gov/pub/irs-pdf/fw9.pdf and passport evidence against https://eforms.state.gov/Forms/ds11_pdf.PDF on October 3, 2026. This was assistant source review, not professional tax/legal review.

External Chrome extension label detection remains limited to its three W-4 labels. The additional forms are supported in the built-in web companion; do not claim universal form recognition.
